# How to read the driver-heuristic tables

This folder is the **paper base-scenario comparison** (n = 43): exact Full, exact Partial, two Driver policies, diesel bound.

Generated by `Post_Analysis/analyze_driver_heuristic.py` from:

| Input file | What it contains |
|---|---|
| `Post_Analysis/base scenario/unified_results_20260408_135323.csv` | Full labeling, Partial labeling, diesel proxy (huge battery) |
| `Post_Analysis/base scenario/driver_heuristic_results_20261016_213428.csv` | Driver heuristic, both policies, `t_sync = 1.0 h` |
| `Post_Analysis/base scenario/driver_heuristic_results_tsync_sweep_20261016_213428.csv` | Driver heuristic, both policies, eight `t_sync` values |

**Paper EV configuration:** battery 750 kWh, CS spacing 60 km, charging power 350 kW, consumption 1.49 kWh/km.

---

## Algorithms in the paper comparison

| Name in tables | Meaning | Variants |
|---|---|---|
| **Full** / `full_route_h` | Exact SPPRC labeling, full recharge at every charging stop | one policy |
| **Partial** / `partial_route_h` | Exact SPPRC labeling, partial recharge (Full is the special case of Partial) | one policy |
| **Driver** | Sequential driver-inspired heuristic | **two charging policies** (see below) |
| **Partial_Diesel_LB** / `partial_diesel_lb_route_h` | Not a competing EV algorithm. Partial labeling with a huge battery (~1e10 kWh): unconstrained energy, HOS still enforced. Used as a diesel-style lower bound. | — |

### Driver heuristic: two variants

| Code | `policy` in D05 | Meaning |
|---|---|---|
| **Driver_FC** | `full` | After a charging stop is opened, fill to the operational SOC cap (idle charging allowed). |
| **Driver_OO** | `overlap` | Charge only while overlapping a mandatory break/rest (`t_sync` window). Idle charging is ~0. |

Headline tables D01–D05 use **`t_sync = 1.0 h`**. Table D06 is the `t_sync` sweep.

Both variants are **deterministic single runs** (one execution per instance × policy). There is no Monte Carlo / multi-seed replication.

## Instance count

Every table uses the 43 tests in `PAPER_INSTANCE_SET_43.txt` (13 short, 15 medium, 15 long). D01 pairwise `n` is 43. D04 `n_instances` is 43 for every strategy.

## File-by-file column dictionary

### `table_D00_instance_id_map.csv`

Short ID used on figures ↔ full instance name. **43 rows** (paper set).

| Column | Meaning |
|---|---|
| `id` | Short label, e.g. `S_cl2_cu4_U` = short, 2 clusters, 4 customers, Unbalanced |
| `instance_clean` | Folder / test name, e.g. `short_cl2_cu4_Unbalanced` |

ID pattern: `S|M|L` (short/med/long) `_cl{K}_cu{N}_B|U`. Single-cluster tests have no `_B/_U` in the file name; the code still tags them `Balanced`.

---

### `table_D01_combined_comparisons.csv`

One row per pairwise comparison. **Candidate advantage** = `(reference − candidate) / reference`. Positive ⇒ candidate is faster.

| Column | Meaning |
|---|---|
| `Comparison` | Human label, “X vs Y” |
| `reference` | Baseline method (the one being beaten if advantage > 0) |
| `candidate` | Method whose advantage is reported |
| `n` | Number of instances with both times present |
| `mean_reference_h` | Mean route time of the reference (hours) |
| `mean_candidate_h` | Mean route time of the candidate (hours) |
| `candidate_better` | Count where candidate time < reference time |
| `reference_better` | Count where reference time < candidate time |
| `ties` | Count where times are equal (tolerance 1e-9 h) |
| `candidate_advantage_avg` | Mean % (and mean minutes) by which candidate is faster |
| `candidate_advantage_min` | Worst instance for the candidate (can be negative) |
| `candidate_advantage_max` | Best instance for the candidate |
| `candidate_advantage_median_pct` | Median % advantage |

Example: “Partial vs Driver (overlap-only)” with n = 43 means Partial is the candidate, Driver_OO is the reference. Average 4.41% means Partial is 4.41% faster than Driver_OO on the 43 common instances.

### `table_D02_per_instance_route_times.csv`

One row per paper instance (**43**). This is the table to quote for per-test numbers.

| Column | Meaning |
|---|---|
| `id` | Short ID (see D00) |
| `instance` | Full test name |
| `problem_size` | `short` / `medium` / `large` (from the name; `med_*` → medium, `long_*` → large) |
| `balance` | `Balanced` or `Unbalanced` (`cl1` tests are tagged Balanced) |
| `full_route_h` | Full-recharge labeling total route time (h) |
| `partial_route_h` | Partial-recharge labeling total route time (h) |
| `driver_fc_route_h` | Driver, full-charge policy (h) |
| `driver_oo_route_h` | Driver, overlap-only policy (h) |
| `partial_diesel_lb_route_h` | Diesel-proxy total route time (h) |
| `driver_fc_minus_partial_min` | Driver_FC − Partial, in **minutes** (positive ⇒ Driver slower) |
| `driver_fc_pct_slower_than_partial` | 100 × (Driver_FC − Partial) / Partial |
| `driver_fc_pct_slower_than_full` | 100 × (Driver_FC − Full) / Full |
| `driver_fc_ev_gap_pct_vs_diesel` | 100 × (Driver_FC − diesel) / diesel |
| `driver_oo_*` | Same gap columns for the overlap-only policy |
| `driver_oo_pct_faster_than_fc` | 100 × (Driver_FC − Driver_OO) / Driver_FC |

Blank cells mean that algorithm has no feasible/exported row for that instance.

### `table_D04_activity_summary_by_strategy.csv`

Mean activity statistics per strategy on the **same 43 instances**.

| Column | Meaning |
|---|---|
| `strategy` | Internal key (`Full`, `Partial`, `Driver_FC`, `Driver_OO`, `Partial_Diesel_LB`) |
| `label` | Display name |
| `n_instances` | Rows contributing to the mean (not a common set) |
| `mean_n_charges` | Mean charging stops |
| `mean_n_breaks` | Mean breaks |
| `mean_n_rests` | Mean daily rests |
| `mean_n_sync_events` | Mean charging stops synchronized with break or rest |
| `mean_n_unsync_charges` | Mean charging stops not synchronized |
| `mean_pct_charge_sync` | Mean share of charging stops that are synchronized (%) |
| `mean_idle_charging_min` | Mean idle (non-overlap) charging time (minutes). ~0 for Driver_OO by construction. |
| `mean_n_unsync_breaks` / `mean_n_unsync_rests` | Mean breaks/rests with no charging overlap |
| `mean_route_h` | Mean route time (h) |
| `mean_computation_sec` | Mean CPU time (s). Labeling is seconds–hours; heuristics are ~0. |
| `mean_total_charging_time_minutes` | Driver only: total plug-in time |
| `mean_total_energy_charged_kWh` | Driver only |
| `mean_num_rule2_sync_stops` | Driver Rule 2: charge because a break/rest is due and a CS is within `t_sync` |
| `mean_num_rule3_forced_charges` | Driver Rule 3: charge forced by SOC / reachability |
| `mean_num_rule4_road_interruptions` | Driver Rule 4: extra stop created on the road |
| `mean_num_customer_interruptions` | Driver: customer-location interruptions |
| `mean_num_cs_passed` | Driver: charging stations passed without stopping |
| `mean_num_guard_break_to_rest` | Driver: break-to-rest guard triggers |

Empty extra columns for Full/Partial/diesel mean those counters were not exported for that strategy.

### `table_D05_driver_rule_statistics.csv`

One row per instance × Driver policy at headline `t_sync = 1.0 h` (**86 rows = 43 × 2**).

| Column | Meaning |
|---|---|
| `id` / `instance_clean` | Short ID / full name |

| `t_sync_hours` | Synchronization look-ahead (h); 1.0 in this file |

| `num_charges` / `num_breaks` / `num_rests` | Event counts |
| `num_charges_sync_with_rest` / `num_charges_sync_with_break` | Charging stops overlapping rest / break |
| `num_rule2_sync_stops` | Stops opened by Rule 2 |
| `num_rule3_forced_charges` | Stops opened by Rule 3 |
| `num_rule4_road_interruptions` | Stops opened by Rule 4 |
| `num_customer_interruptions` | Customer-site interruptions |
| `num_cs_passed` | CS passed without a stop |
| `num_guard_break_to_rest` | Break upgraded/converted to rest by the HOS guard |
| `num_cs_on_route` | CS nodes on the physical route |
| `total_charging_time_minutes` | Plug-in duration |
| `total_idle_charging_time_minutes` | Charging time **beyond** break/rest overlap (the FC vs OO difference) |
| `total_energy_charged_kWh` | Energy taken from the grid |
| `final_soc_kWh` | SOC at the destination |
| `total_driving_time_hours` / `total_service_time_hours` / `total_break_time_hours` / `total_rest_time_hours` | Time-budget split |

### `table_D06_tsync_sensitivity.csv`

One row per (`t_sync_hours`, policy). Sweep values: 0, 0.25, 0.5, 0.75, **1.0 (headline)**, 1.25, 1.5, 2.0 h. Each cell is a **single deterministic run** of Driver on the 43 paper instances. `mean_route_h` and `mean_route_h_common_with_partial` are identical.

| Column | Meaning |
|---|---|
| `t_sync_hours` | Look-ahead used to open a synchronized charging stop |
| `policy` | `Driver_FC` or `Driver_OO` |
| `n_instances` | 43 |
| `mean_route_h` | Mean over the 43 |
| `mean_route_h_common_with_partial` | Same 43 (kept for compatibility) |
| `mean_pct_slower_than_partial` | Mean % gap vs Partial |
| `mean_charges` / `mean_breaks` / `mean_rests` | Mean event counts (over 43) |
| `mean_idle_charging_min` | Idle charging; 0 for Driver_OO |
| `mean_rule2_sync_stops` | Mean Rule-2 stops |
| `mean_rule4_road_interruptions` | Mean Rule-4 stops |

At `t_sync = 0`, Rule 2 cannot fire (`mean_rule2_sync_stops = 0`).
